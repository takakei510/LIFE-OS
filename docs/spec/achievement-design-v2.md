## 1. 中核理念

**世界を広げるのも、ひとつの世界を深めるのも、どちらも冒険である。**

LIFE OSは人生を管理するTODOアプリではない。実績は「初めて触れた世界」と「好きな世界を深く楽しんだ軌跡」の両方を表す。

- 全実績コンプリートを標準の目標にしない。多数の未解除実績があることは正常。
- 広く探索するプレイヤー、特定分野を極めるプレイヤー、両方を楽しむプレイヤーを等しく尊重する。
- 解除率や総XPだけで人の価値・技能の優劣を評価しない。
- 実績ツリーの枝の伸び方と代表的な到達点が、プレイヤーの個性を表す。
- 入力負担を増やさず、現実の体験を優先する。同じ情報は二度管理しない。

## 2. 実績の共通必須項目

各実績は次の項目を持つ。既存のNotionデータ構造・名称を尊重し、**この仕様だけを理由にプロパティを増やさない**。

| 項目 | 共通ルール |
| --- | --- |
| 実績名 | ゲームらしく短く、少しワクワクする名前。達成内容を誤認させない |
| カテゴリ | 既存の大分類を使う。趣味名のためにカテゴリを乱立させない |
| Tier | Common / Uncommon / Rare / Epic / Legendary |
| XP | 基準値は10 / 25 / 50 / 100 / 250。既存実績の値を無断で変更しない |
| 達成条件 | 第三者にもYes/Noで判定できる具体的な条件 |
| 解除状態 | 原則1実績につき1回だけ解除。繰り返しの達成は重複付与しない |

既存の表示・ライフサイクル・秘密表示・前提Relationなどは、既存実装・設計に従う。

## 3. 5つの実績系統

一つの趣味に対して、次の系統を組み合わせる。

1. **初体験**：初めて行う／初めて完成させる（例：小説を1冊読み終える）
2. **積み重ね**：累計回数・冊数・作品数・場所数など（例：小説を累計5冊読み終える）
3. **発見**：自分の好み・新しいジャンル・お気に入りを見つける（例：読み終えた小説からお気に入りを1冊選ぶ）
4. **挑戦・成長**：初めての技法・表現・成果物・難しい体験（例：自分の演奏を録音して聴く）
5. **共有**：紹介・共同体験・感想の交換（例：すすめた小説を相手が読み、お互いに感想を伝え合う）

系統は**企画上のタグ・観点**であり、現時点でNotionに新しい必須プロパティを追加する指示ではない。

## 4. 趣味ごとの専門ツリー

カテゴリ（例：育成、探索、創作）と、趣味・活動の専門ツリー（例：読書、映画、ギター、ゲーム、プラモデル、料理、旅行、語学、研究）は別概念。

- 一つの専門ツリーに複数の系統を設ける。
- 簡単な入口から、長年の経験を要する尖った枝まで用意する。
- すべてのプレイヤーが到達できる必要はない。ただし達成条件は公平・明確で、無理な危険行動を促さない。
- 専門ツリーを追加するとき、既存カテゴリと重複した管理元を作らない。
- ツリーの所属や見せ方は、実績の解除前提と混同しない。**同じ分野だからという理由だけで線を引かない。**

## 5. 累計・マイルストーン実績

冊数や作品数の累計実績を積極的に作る。例：小説 **1 / 5 / 10 / 25 / 50 / 100 / 500 / 1000冊**。

- 数字は分野に応じて調整する。すべての趣味に同じ段階を機械的に当てはめない。
- 「累計」の起点・対象・数え方を明記する（例：小説を読み終えた冊数。再読や短編集の扱いは当該実績群で統一）。
- 一つの体験で複数マイルストーンに達した場合、各実績はそれぞれ一度だけ解除可能。二重の行動記録は要求しない。
- 日々の記録、連続日数、証拠提出を原則強制しない。本人の申告で解除できる設計を基本とする。
- 累計の値は実績解除の条件であり、恒常的な習慣管理やランキングを義務化するものではない。
- 大きい数値だけで埋めず、発見・挑戦・共有の枝も充実させる。

## 6. 前提条件とチェーン

- 前提は**後続の体験に実際に必要な経験・成果物・理解**に限る。
- 複数前提を指定する場合はすべて解除で公開・挑戦可能（AND）。枝分かれ・合流・独立実績を許容する。
- ただの同カテゴリ、難易度差、見栄えのための接続はしない。
- 累計の「5冊→10冊」などは内容上の包含関係が明確なため自然なチェーン候補。ただし全件を強制的に一本の線で結ばない。
- 自己依存・循環・存在しない前提を禁止し、読み取り不完全な関係を達成済みとみなさない。
- 未発見実績の秘密情報はクライアントに送らない。既存の解除済み記録を後から取り消さない。
- クラスタの発見・版管理・永続化は `docs/architecture/achievement-tree.md` に従い、未実装機能を実装済みと扱わない。

## 7. TierとXPのバランス

| Tier | 基準XP | 基本的な目安 |
| --- | ---: | --- |
| Common | 10 | 入口となる一度の体験 |
| Uncommon | 25 | 少し意識すれば到達できる体験・積み重ね |
| Rare | 50 | 一定の経験や挑戦が必要 |
| Epic | 100 | 長期的な積み重ね・大きな挑戦 |
| Legendary | 250 | 人生の節目や、極めて長い専門的な積み重ね |

Tierは**人の上手さの判定ではなく、条件の到達難度・希少性・経験の深さ**を表す。実績ごとの数値閾値とTierは、同じ専門ツリー内の整合性をレビューして決める。例示の「1000冊」を自動的にLegendaryへ確定しない。

## 8. 経験量マイルストーンと専門ツリーの到達点

**共通の設計基準：20時間は初期のまとまった経験、1万時間は生涯級の象徴的な最上位到達点。** これらはLIFE OS独自のゲーム設計上の目安であり、技能の熟達を保証する科学的な閾値ではない。

| 経験量の目安 | 位置付け | 設計上の用途 |
| --- | --- | --- |
| 初回〜20時間程度 | 入口・最初の成長 | Common〜Uncommonを中心に、気軽な成功体験を用意 |
| 20〜100時間程度 | 趣味を楽しみ始める | 小さな積み重ね、最初の発見・挑戦 |
| 100〜1000時間程度 | 専門ツリーの深化 | 多様な枝、長期の体験、Rare〜Epicの候補 |
| 1000〜5000時間程度 | 大きな積み重ね | Epic〜Legendaryの候補 |
| 5000〜10000時間程度 | 生涯級の没頭 | 特に象徴的なLegendaryの候補 |

この時間帯は**厳格なTier判定表ではない**。体験の希少性、難易度、費用、アクセス可能性、安全性、活動の多様性を加味して個別に決める。時間だけで価値を決めず、すべての分野に1万時間実績を強制しない。

### 時間と実際の解除条件を分ける

- 原則として、時間は**企画時の難易度校正用の裏側の目安**。実際の解除条件には、その趣味で自然に数えられる冊数・作品数・完成品・体験・訪問場所などを優先する。
- 読書：小説1冊を平均4〜6時間と仮定すると、20時間は約3〜5冊、1万時間は約1667〜2500冊。**読書量の象徴的な最上位候補は累計2000冊**（平均5時間なら約1万時間）。「5冊で必ず上達」「2000冊で必ず熟達」とは主張しない。
- 映画：平均2時間と仮定すれば1万時間相当は約5000作品。ただし作品数と鑑賞時間は同義ではなく、候補値は分野別にレビューする。
- ギター：累計演奏時間のほか、初めての録音・人前での演奏・完成した曲など、具体的な成果や体験の枝を用意する。
- 料理・旅行・プラモデルなど：1回あたりの所要時間のばらつきが大きい場合、無理に時間換算せず、作った種類・完成作品・訪問先・新技法などで設計する。
- 正確な累計時間を記録していない人に、過去の時間の再計算や継続的なタイマー入力を強制しない。

### 「ツリー最上位」と「趣味の終わり」は別

- 専門ツリーには長期的な目標となる**象徴的な最上位実績**を設けてよい。ただし、達成後も趣味は続き、新しい枝や別の体験を追加できる。
- すべての枝を最上位まで伸ばすことは求めない。代表実績の価値を守るため、無意味な上位閾値の乱造を避ける。
- 一つの分野の深さには「量」「ジャンル」「制作・表現」「交流」など複数の方向がある。大量に経験した人と特定の領域を掘り下げた人は、別々の到達点で個性を示せる。
- 時間や作品数の実績は経験の証明であり、技術・知識・資格の客観的な保証ではない。

### 参考となる考え方の扱い

「最初の20時間」はJosh Kaufmanの学習に関する提案、「1万時間」は熟達研究を背景に普及した象徴的な数字として参照する。両者は**到達できる技能レベルや活動の性質が異なる**ため、同一尺度で上達を断定しない。実証的な一般法則として採用せず、LIFE OSのゲームバランスを考える際の着想として扱う。

## 9. プロフィールと将来の複数ユーザー対応

- 総XP・Levelに加え、専門ツリーごとの代表実績・到達した枝・分野の広がりを見せる。
- 「読書1000冊」などの具体的な到達点は、単なる全体解除率より専門性を伝えやすい。
- 全体解除率を唯一の成績にしない。新しい実績の追加で既存プレイヤーの価値が下がるような見せ方を避ける。
- 「特化している」は**経験の蓄積の可視化**であり、資格・技能の客観的な保証ではない。
- 将来の公開プロフィールや他者との比較には、公開範囲・プライバシー設定を別途設計する。

## 10. 新規実績の共通レビュー手順

実績案を追加する前に次を確認する。

- [ ] 体験・積み重ね・発見・挑戦・共有のどれに該当するか説明できる
- [ ] 条件が具体的でYes/No判定でき、解除は一度きり
- [ ] 上手さの主観的採点や、毎日の管理・証拠提出を要求しない
- [ ] 既存実績と実質的に重複しない（類似条件・累計閾値を照合）
- [ ] 専門ツリー内で難易度とTier/XPの順序が自然\n- [ ] 20時間〜1万時間の目安は校正に使い、活動に不自然な時間管理を要求していない\n- [ ] 最上位候補は象徴的で、達成後も別の枝が楽しめる
- [ ] 前提関係がある場合、内容上の必然性があり循環しない
- [ ] 名前・カテゴリ・条件・Tier・XPが整合し、無理な危険行動を促さない
- [ ] 既存データや解除記録を無断で書き換えない
- [ ] 新しい記録元を増やさない

**運用手順**：候補を作る → 重複・バランス・前提をレビュー → ユーザー承認 → Notionへ登録 → 公開表示を確認。**設計書の更新だけで実績を自動登録しない。**

## 11. 最初のモデルケース：読書

| 系統 | 実績例 | 達成条件の例 |
| --- | --- | --- |
| 初体験 | 物語の扉 | 小説を1冊読み終える |
| 積み重ね | 本棚の住人 | 小説を累計5冊読み終える |
| 積み重ね | 千の物語を歩く | 小説を累計1000冊読み終える |\n| 積み重ね | 二千の物語を渡る | 小説を累計2000冊読み終える（読書量の最上位候補） |
| 発見 | 心に残る一冊 | 読み終えた小説からお気に入りの1冊を選ぶ |
| 挑戦 | 未知の書架 | 今まで読んだことのないジャンルの小説を1冊読み終える |
| 共有 | 物語の架け橋 | すすめた小説を相手が読み、お互いに感想を伝え合う |

これらは**候補例**であり、Notion登録済みの実績や確定Tierを意味しない。具体的な読書ツリーの全ノード・計数ルール・前提関係は別途レビューして確定する。

## 12. 既存設計との関係

本書は、実績の**企画・評価・拡充に関する最新版**。旧方針の「上達より体験」「1回で解除可能」「管理しない」は維持する。「1回で解除可能」は**解除イベントが一度きり**という意味であり、累計条件を禁止しない。

実装済みのAPI・Notionプロパティ・既存実績の条件・XP・解除記録は変更しない。実績ツリーの実装・秘密表示・クラスタ契約は `docs/architecture/achievement-tree.md` を優先する。矛盾が生じたら、実装を暗黙に変更せず設計レビューで解消する。

> LIFE OSは「何者になるか」を競うゲームではない。**どれだけ世界に触れ、どれだけ深く楽しんだか**を表現するゲームである。
