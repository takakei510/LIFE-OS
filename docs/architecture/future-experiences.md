# 将来構想の設計案

状態はレビュー待ち。各構想は、現実で出会ったものを思い出せるか、次に触れてみたい体験が見つかるかで評価する。途中でやめても記録や進捗を失わない設計を共通条件とする。

| 構想 | 最小の体験 | データと進捗 | 着手条件 |
| --- | --- | --- | --- |
| 個別図鑑 | カフェ・映画・読書などから1分野を選び、出会った対象を集めて振り返る | 対象の識別子と本人の訪問・視聴などの記録を分ける。同じ対象への複数の記録を保持し、任意で冒険ログを参照する | 1分野で、同名の対象・再訪・修正を扱えることを確認 |
| 進捗型実績 | 異なる体験をいくつか積み、本人が条件を見て達成する | 版付き条件と、適格な記録の参照を持つ。同一記録の再送は1回。ログを必須にせず、本人が体験した項目を選べる | 実績ツリーの前提と混同しない表示、再送・訂正・達成済みの扱いを検証 |
| 育成スキルツリー | 一つのテーマで試した経験を並べ、次の試し方を選ぶ | テーマと体験の関係を持つ。上達の点数付けはせず、試した方法や成果物を表示する | 既存の実績マップと役割を比較し、独立した画面が必要か一つのテーマで試す |
| 季節・ランダムイベント | 季節や気分に合う体験を、好きなときに受け取る | イベントの開催期間と体験候補を管理する。季節を逃しても過去の記録は残り、ランダム候補は引き直せる | 日付境界、表示の再現性、スキップ後の挙動を確認 |
| 人生マップ | 選んだ記録を時期や場所のまとまりで眺める | 冒険ログとStoryの参照から表示を作る。場所は本人が入力した粒度を使い、地図表示には別途同意を得る | まず時系列で試し、場所が未入力のログでも振り返れることを確認 |

## 既存の取り組みとの接続

- **実績マップ**は前提関係と発見を表示する。クラスタ解放は指定した実績セットを基準にし、図鑑の登録件数やStoryの作成を自動で解放条件にしない。個別の実績条件を増やす場合は、次の体験に実際に必要な経験を選ぶ。
- **探索案内人**は気分・時間・環境から公開済みの実績やクエストを探す。既存の相談文生成と条件絞り込みを入口にする。将来の提案では、本人が明示的に選んだデータだけを使い、未発見の内容と非公開ログを候補データから除外する。
- **Story**は本人が選んだ体験をつなぐ。将来の人生マップには閲覧できる記録を参照し、同じ体験を別の場所へ複製しない。

## 進め方

冒険ログの管理を先に整え、手動Storyと個別図鑑1分野を小さく試す。進捗型実績は、1件の記録を再送・訂正したときの数え方と、条件の新版への移行を決めてから実装する。育成ツリーと人生マップは、既存の実績マップやStoryで満たせない体験が確認できた段階で設計を深める。イベントは一つの任意参加イベントで表示とスキップを検証してから増やす。
