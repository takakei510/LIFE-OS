# 実績マップ — 複数ルートの星図（プレビュー）

2026-11-06 / Issue #70。人生の優劣やタスクの消化ではなく、触れた世界と次の体験のつながりを眺める画面。

## 採用方針（2026-11-06更新）

単一の中央ルートや6カテゴリの固定ツリーを必須にしない。根が複数ある小さなクラスタ、独立実績、複数の流れが合流する実績を許容する。クラスタは世界を見渡すためのまとまりであり、人生の成長度を測る段階ではない。

根の周辺から放射状に広がる。複数の根が同じ後続実績に接続しても、実績は1つだけ表示する。意味上のクラスタは重複所属してよく、分類は解除条件から分離する。カテゴリを強制的な親にせず、レイアウト上のまとまりから前提関係を推測しない。

実績・関係のRepository正規化、公開可能なグラフへの変換、配置計算、画面操作を分離する。件数・座標・実績名を画面へ固定しない。配置は同じID/関係なら入力順に依存せず再現可能とし、文字とバッジの衝突を避ける。追加や接続変更で周辺の配置が変わることはある。恒久的な座標保存や追加前の配置固定は今回含めず、必要時はレイアウト専用の保存先として別に設計する。

### 前提条件と発見

1. **実績の複数前提**：指定した実績をすべて解除したときだけ内容を公開し、挑戦可能とする（AND）。一部だけの解除では開かない。
2. **クラスタの解放**：指定された前段クラスタの固定対象セットをすべて解除すると、後続クラスタの指定ルートが現れる。複数の前段セットを要求する場合もAND。
3. **すでに解除された実績・発見済みクラスタ**：設定変更で閉じ直さない。実績の達成は自動付与せず、開いた後に本人が達成条件を確認して解除する。

通常の未発見実績は今の「？？？」表示を維持する。未発見クラスタは将来、名前・対象ID・所属件数・内部の接続を丸ごと公開モデルから除外する。「？？？」ノードを並べて規模や内容を推測できる状態にしない。発見後も、内部の各実績に前提があればその判定を続ける。非公開状態を検索結果・選択欄・URL詳細・クライアントのデータから漏らさない。

### クラスタの全クリア対象（次段階のデータ契約）

クラスタの現在の全所属を動的に数えて解放条件にしてはいけない。以下をRepository境界で正規化する設計とする。今回、Notionプロパティの追加は行わない。

| 要素 | 契約 |
| --- | --- |
| クラスタID | 名前を変えても変わらない識別子。複数所属を許す |
| 対象セットID・版 | 例：`photo-basics@1`。公開後の対象ID集合は不変 |
| 対象実績ID集合 | 重複除外した明示的な有限集合。空集合は設定不備として扱う |
| 解放条件 | 必要な対象セットの版を明示。すべての対象実績の解除を要求 |
| 解放先 | 後続クラスタIDとルート実績ID。分類の所属とは別の関係 |
| 発見記録 | プレイヤーID・クラスタID・発見日時・適用したセット版。再送で増殖しない |

対象実績を追加したい場合は新しい版を作り、既存の解放条件の参照先を勝手に置き換えない。新規実績の追加で既存プレイヤーの必要数が増えたり、開いたクラスタが閉じたりしない。発見記録の永続化・認証・同時更新への対応を用意する前にクラスタ解放を公開しない。

クラスタと実績の依存を合わせて循環・自己依存を検査する。後続クラスタに隠された実績を、そのクラスタ自身を開くための対象に含めない。欠損、非Active化された対象、読み取り不完全、空のセットは条件を満たしたと扱わず、管理側で修正する。発見済み記録は維持する。

### 実績内容の作成基準

基準は「日々の中で気づいたこと」「新しく挑戦したいこと」「努力して会得したこと」。前提には、次の体験に実際に必要な経験・成果物・理解を指定する。次の条件が前の経験を利用することを文章で確認できるようにする。

- 適切な例：「自分で撮影した写真を選ぶ」＋「写真を説明する短文を作る」→「選んだ写真と自分の文章で小作品を作る」。成果物を両方使う。
- クラスタの例：撮影・選別・構成を試す固定セットを終え、その経験を利用する小作品制作のクラスタを開く。
- 避ける例：写真の実績を開くために無関係な散歩を10回要求する、同じ行動を重複して数える、日数や連続記録だけで足止めする。

単に難易度が高そう、カテゴリが同じという理由だけで前提を増やさない。既存実績へ後付けで前提や新しい条件を付与する場合は、内容と到達可能性をレビューした別のデータ更新として扱う。今回の画面更新では既存内容・XP・Notion保存値を変更しない。

## 画面と操作

### 視認性改善（2026-11-06）

達成済みは緑の背景・左の帯・チェック付き「達成済み」ラベルで明示する。レア度は既存の六角バッジ枠とカード内Tier名へ反映し、達成状態と混同しない。全体図の点でもTier枠を保ち、達成済みはチェック・塗り・外周で区別する。未発見のTierは非送信のまま、未設定TierはCommonへ補完しない。NotionのTier値・解除記録は変更しない。

全199件の自動縮小を初期表示にしない。「つながりのある実績」と「ひとつから始まる実績」を切り替え、後者は12件ずつ表示する。カテゴリ内に前提関係がなければ後者から開始する。起点または実績名のボタンから100%以上の読める倍率で移動できる。未解除を理由にカード全体を薄くしない。

「全体を表示」は位置を把握する俯瞰専用とし、42%未満では縮小カードの代わりに画面上で20pxを保つ点を表示する。点の選択、実績選択欄、「読める大きさへ」で詳細表示に戻る。カードの文字は16pxを基準にし、前提線・未発見の枠・背景のコントラストを確保する。検索は現在のカテゴリ/見方が対象で、独立実績の検索はページ分割前に行う。

実績一覧の「ツリー」から `/achievements/tree` を開く。PCは全実績、スマホは探索カテゴリ（なければ最初のカテゴリ）で開始し、「すべての実績」へ切り替えられる。カテゴリ指定URLも使用可能。

- ドラッグ、2本指のピンチ、拡大・縮小ボタン、全体表示。
- PCはCtrl/Meta＋ホイール。通常のホイールはページスクロール。
- 矢印ボタン、マップにフォーカスした状態の矢印キー、実績選択欄でも操作できる。
- 検索は公開可能な名前・条件・説明・カテゴリだけを対象とし、該当ノードを強調する。選択欄から中央へ移動できる。
- 解除済み、挑戦可能、前提未解除、関係を確認中を文字と枠で区別する。既存の六角バッジ・Tier・モチーフを再利用する。

線はNotionの既存 `Prerequisites` のみ。複数前提はすべて解除済みになったとき挑戦可能となる。独立実績には架空の親・カテゴリの枝を追加しない。カテゴリ外のノードや非公開実績への線は描かない。カテゴリ絞り込みにより表示の接続数が減っても、解除判定は全データで行う。矢印の先が後続実績であり、後続ほど外側のリングに配置する。

## Repositoryと公開境界

`readAchievementTreeRecords` がActiveのAchievementsを全ページ読み取り、アーカイブ・ゴミ箱・別データソースを除外する。埋め込みRelationの `has_more` がある場合はproperty取得APIを最後までページングする。途中失敗・不正なカーソルは完全取得とみなさない。

Application層の `buildTreeModel` が前提条件と循環を判定し、クライアント用DTOへ変換する。欠損参照、不完全なRelation、自己参照、循環とその下流は「関係を確認中」とし、新規解除を許可しない。すでに解除された実績の記録は維持する。

ユーザー承認により、前提未解除の実績は未発見として名前を「？？？」にし、条件・説明・Tier・XP・Domain・元URLをクライアントへ送らない。カテゴリと前提件数だけは表示する。未解除のHidden実績はノード・ID・接続先を送らない。未発見のバッジに実績IDを渡さず、登録モチーフから内容が推測されることも避ける。

ツリーだけの表示隠しでは一覧や詳細に内容が残るため、Snapshotも同じ公開変換を通し、一覧・詳細の未発見表示を統一する。HOMEの探索候補からは前提未解除を除外する。実績解除時はサーバーで最新の前提関係を再読し、挑戦可能な実績だけ既存のUnlocked/Unlocked Atを更新する。XP値、計算式、解除条件は変更しない。解除済みへの再送は日付を再更新しない。
