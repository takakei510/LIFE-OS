# 実績ツリー（プレビュー）

2026-11-06 / Issue #70。人生の優劣やタスクの消化ではなく、触れた世界と次の体験のつながりを眺める画面。

## 画面と操作

実績一覧の「ツリー」から `/achievements/tree` を開く。PCは全実績、スマホは探索カテゴリ（なければ最初のカテゴリ）で開始し、「すべての実績」へ切り替えられる。カテゴリ指定URLも使用可能。

- ドラッグ、2本指のピンチ、拡大・縮小ボタン、全体表示。
- PCはCtrl/Meta＋ホイール。通常のホイールはページスクロール。
- 矢印ボタン、マップにフォーカスした状態の矢印キー、実績選択欄でも操作できる。
- 検索は公開可能な名前・条件・説明・カテゴリだけを対象とし、該当ノードを強調する。選択欄から中央へ移動できる。
- 解除済み、挑戦可能、前提未解除、関係を確認中を文字と枠で区別する。既存の六角バッジ・Tier・モチーフを再利用する。

線はNotionの既存 `Prerequisites` のみ。複数前提はすべて解除済みになったとき挑戦可能となる。独立実績には架空の親・カテゴリの枝を追加しない。カテゴリ外のノードや非公開実績への線は描かない。カテゴリ絞り込みにより表示の接続数が減っても、解除判定は全データで行う。

## Repositoryと公開境界

`readAchievementTreeRecords` がActiveのAchievementsを全ページ読み取り、アーカイブ・ゴミ箱・別データソースを除外する。埋め込みRelationの `has_more` がある場合はproperty取得APIを最後までページングする。途中失敗・不正なカーソルは完全取得とみなさない。

Application層の `buildTreeModel` が前提条件と循環を判定し、クライアント用DTOへ変換する。欠損参照、不完全なRelation、自己参照、循環とその下流は「関係を確認中」とし、新規解除を許可しない。すでに解除された実績の記録は維持する。

ユーザー承認により、前提未解除の実績は未発見として名前を「？？？」にし、条件・説明・Tier・XP・Domain・元URLをクライアントへ送らない。カテゴリと前提件数だけは表示する。未解除のHidden実績はノード・ID・接続先を送らない。未発見のバッジに実績IDを渡さず、登録モチーフから内容が推測されることも避ける。

ツリーだけの表示隠しでは一覧や詳細に内容が残るため、Snapshotも同じ公開変換を通し、一覧・詳細の未発見表示を統一する。HOMEの探索候補からは前提未解除を除外する。実績解除時はサーバーで最新の前提関係を再読し、挑戦可能な実績だけ既存のUnlocked/Unlocked Atを更新する。XP値、計算式、解除条件は変更しない。解除済みへの再送は日付を再更新しない。
