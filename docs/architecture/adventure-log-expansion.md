# 冒険ログ拡張の設計案

状態はレビュー待ち。冒険ログは、残したい体験を後で振り返るための本人用の記録とする。

## 現状と実装順

本番では、テキスト・日時・場所・写真を保存し、HOMEと冒険ログ一覧で振り返れる。実績への関連付けは任意で、一覧の「思い出を残す」から自由ログを作成できる。Notionに `Favorite`、`Lifecycle`、`Player`、`Media` があり、Webからのお気に入り操作と編集・アーカイブを追加する。

| 段階 | 範囲 | 完了条件 |
| --- | --- | --- |
| 1. 記録を整える | 詳細、お気に入り、テキスト編集、アーカイブ | 実績関連ログと自由ログの両方を開ける。変更は再表示後も一致し、アーカイブはHOMEと通常一覧から外れる |
| 2. 音を残す | 音声ファイルの選択、保存、詳細での再生 | 写真と音声が混在したログを再表示でき、音声失敗時も保存済み本文と写真を利用できる |
| 3. その場で録る | ブラウザー録音、試聴、録り直し | 対応端末で録音から保存まで完了し、許可拒否・非対応時はファイル選択に戻れる |
| 4. 旅を綴る | 選んだログの並べ替え、見出しと短文、非公開のStory保存 | 選択順で再表示でき、元ログの編集やアーカイブを安全に扱える |

## 1. 自由ログと記録管理

- 一覧の「思い出を残す」と実績解除後の入口は、既存の作成フォームを使う。詳細で自由ログと実績関連ログを同じように扱う。手動の日記タイトルや場所は任意とする。
- 詳細では日時・メモ・場所・添付をまとめる。お気に入りは `Favorite` を明示値で設定し、同じ操作の再送は同じ結果とする。お気に入りで絞り込めるようにする。
- 初回の編集対象はタイトル・日時・メモ・場所。既存の入力制限と日本時間の扱いを再利用する。添付や関連実績の変更は、個別の権限・再送・競合対策が揃った段階で追加する。
- アーカイブは対象名を確認してから `Lifecycle = Archived` を設定する。アーカイブ専用一覧から復元できる。通常の詳細URLとHOMEではアーカイブ済みの本文と添付を出さず、復元は本人用アーカイブ一覧に置く。
- 書き込み前に、サーバーで対象DB・ページ・Player・Lifecycleを再取得する。フォームの編集時点の版と照合し、古い場合は入力を保持して再読込を促す。Webからの同一ログ操作は直列化する。Notionからの直接編集との完全な排他は別途検証する。

## 2. 音声ファイルの保存と再生

初回は1ログにつき音声1件、最大5 MiBを設計値とする。公開前に既存ワークスペースで上限を再確認する。形式は対象端末で再生確認できたMIMEとコンテナだけを許可リストに入れ、候補はMP3・M4A・WebMとする。

1. ブラウザーから、既存写真と同じ考え方の非公開一時保管へ直接送る。許可はログ作成・編集の対象、所有者、パス、期限、容量、形式に結び付ける。
2. サーバーで実サイズ・MIME・コンテナを確認し、Notionの `Media` に転送する。写真と音声を同じファイル一覧として正規化し、保存済み添付を保ったまま追加する。結果が不明な更新は照会してから再送し、同一ファイルを重複添付しない。
3. 詳細で本人の操作により再生する。HOMEは音声の存在だけ示す。期限付きURLは権限確認後に再取得し、読み込み失敗時は詳細で再試行できるようにする。
4. 一時保管の清掃は専用プレフィックスと期限で絞る。添付の途中失敗は本文の保存と分けて通知し、失敗した音声だけをやり直せるようにする。

## 3. ブラウザー録音

録音ボタンを押した時点でマイク許可を求め、録音中・経過時間・停止を表示する。停止後は再生してから添付を選べる。画面離脱・破棄・停止でマイクを解放する。端末ごとに録音できる形式を選び、再生・転送の対応形式と一致させる。上限到達時は停止して試聴へ進む。iOS SafariとAndroid Chromeで録音、割り込み、許可拒否、再生を確認する。

## 4. Story連携

Storyはタイトル、本人のコメント、順序付きのログ参照を持つ。初期版は選んだログを手動で並べて保存する。メモや写真、音声の本体は元ログを参照し、編集が反映される形にする。アーカイブ済み・閲覧できないログは内容を表示せず、順序上に利用できない項目として残す。閲覧・編集とも本人の範囲で行う。

AIによる構成案は後段。対象ログと送る項目を本人が確認してから明示操作で送信し、提案を編集して保存する。写真・音声・場所はそれぞれ別に共有を判断できる設計とする。

## 実装時の確認

- 既存ログの表示、自由ログの作成、お気に入りの再送、同時編集時の競合、アーカイブからの復元。
- 第三者のページID、別DB、期限切れの送信許可、実体と拡張子の不一致、容量超過、写真と音声の混在、転送途中の失敗。
- 添付・ログ・Storyの失敗時も実績とクエストの結果は独立して確定する。ログを書いたこと自体はXPの条件に含めない。
- 認証付きプレビューで読み込みと操作を確認する。実際の書き込みの検証先は、事前に分けたデータか本人が記録したい体験とする。
